## 2026-06-17 (NF-C1 — news-context-shift sequencing, wired OFF)
- **NF-C1 (spec §4.4) — news-context-shift sequencing built, WIRED OFF by default.** When an ongoing story's tracked FACT changes day-over-day, the brief gains one concise, sourced "what changed" note — data-to-data per §4.3 (every delta carries old_ids AND new_ids; never diffs prose or a prior brief), only past a per-type materiality bar. New `agents/thread_tracker.py`: Stage 0 embedding-match today's brief stories to prior threads (`cluster_id` = the 48h spine; the stored embedding bridges the 7-day context), Stage A cheap-model structured-fact extraction, `classify_delta` type-family-consistent diff across the 7 delta types (magnitude / cumulative / status / reversal / scope / attribution / forecast). Persists to a new Supabase **`tracked_threads`** table (migration `create_tracked_threads_nf_c1`; `tracked_threads.sql` kept for reproducibility; service-role round-trip verified); **Monday-06:00-JST weekly hard reset (§4.2)** owned by the module. Renders BOTH a `## 📈 What Changed` subsection (deterministic splice) AND inline-in-theme (LLM weaves the verified note, figures preserved); placement is config (`sequencing_placement`). Wired into `writer.run_writer` gated by `sequencing_enabled` (**default false ⇒ brief byte-for-byte unchanged**, verified: `build_user_prompt` identical off vs on). Telegram brief only. `tests/test_thread_tracker.py` (62 checks); suite 27/27. Read-only `--simulate` over the last 7 real briefs produced clean status/scope deltas with backing article IDs, zero prose-derived. **To enable:** set `sequencing_enabled: true` (changes the live Telegram brief — do with a watched first run). Follow-ups backlogged: NF-C1b (WhatsApp), NF-C1c (settings placement toggle). (`5b93fdf`)

## 2026-06-13 (NF-F2 — char-overrun monitor)
- A brief that exceeds its theme-scaled character cap now **flags in the run log** (`⚠ CHAR OVERRUN: <n> chars > cap <c> (+Δ, +pct%)`) instead of passing silently — surfaces the ~15–17% editorial drift noted in spec §15. New pure helper `agents/char_monitor.py` with a config-gated tolerance (`writer_char_overrun_warn_ratio`, default `1.0` = flag any overrun; e.g. `1.15` = only flag >15% over — no hard-coding), wired into **both** brief generators: the Telegram writer (`agents/writer.py`) and the WhatsApp brief (`run_whatsapp_brief.py`, which previously logged no char count at all).
- Deliberately a **quality** flag, not a run-health failure: it does **not** touch `agent_runs.status`, so the §4.5 watchdog still treats an over-cap-but-successful brief as success (no schema change, no daily false alarms).
- Tests: `tests/test_char_monitor.py` (18 checks — over-cap flags, within-cap/tolerance silent, bad inputs never crash); full repo suite green, no regressions.
